## Purpose

定义统一工作台能力：以单一入口（命令 + ribbon）打开三步向导——查询（AI 生成三种脚本 / 手写三种脚本 / 既有三来源）、确认（执行查询并核对命中文件）、执行（分组操作目录分发给既有 Action 管线）。工作台为编排层，不改变既有命令与安全模型（提案-确认、备份回滚）。

## ADDED Requirements

### Requirement: 三步向导与单一入口

系统 MUST 提供命令与 ribbon 图标打开工作台，工作台 MUST 以 查询 → 确认 → 执行 三步向导组织流程，各步骤间往返导航 MUST 保留已填写的查询状态。既有命令 MUST 全部保留可用。

#### Scenario: 打开工作台并完成一次完整流程

- **GIVEN** 用户通过命令或 ribbon 打开工作台
- **WHEN** 用户依次完成 查询 → 确认 → 执行
- **THEN** 全流程 MUST 在同一弹窗内完成，且任一步骤可返回上一步

#### Scenario: 返回上一步保留状态

- **GIVEN** 用户在确认步骤点击返回查询
- **WHEN** 查询步骤重新渲染
- **THEN** 已选择的来源与已填写的查询文本 MUST 保留

### Requirement: 查询步骤支持多来源

查询步骤 MUST 支持：AI 生成（自然语言 → 三语法提案）、手写 DQL、手写搜索语法、手写 Bases、搜索面板结果、剪贴板、当前文件链接。AI 生成与手写 DQL/搜索 MUST 经统一执行器执行；既有三来源 MUST 经既有 Reader 执行。来源切换 MUST 保留各来源各自的状态。

#### Scenario: AI 生成来源

- **GIVEN** 用户选择 AI 生成并输入自然语言
- **WHEN** 规划完成
- **THEN** 系统 MUST 展示三语法提案（复用选择器交互），用户选定目标后进入确认步骤

#### Scenario: 手写脚本来源

- **GIVEN** 用户选择手写 DQL / 搜索 / Bases 并输入脚本
- **WHEN** 用户请求执行
- **THEN** 系统 MUST 先做语法检查（见语法检查需求），通过后执行并进入确认步骤

#### Scenario: 既有三来源

- **GIVEN** 用户选择搜索面板 / 剪贴板 / 当前文件链接
- **WHEN** 用户请求执行
- **THEN** 系统 MUST 经对应既有 Reader 读取并进入确认步骤；来源不可用时 MUST 给出与既有命令一致的提示

### Requirement: 查询脚本语法检查

系统 MUST 提供脚本语法检查：DQL 经 Dataview 只读试跑校验（未安装 Dataview 时 MUST 提示无法检查）；搜索语法与 Bases MUST 做结构检查（括号/引号配平、操作符与键白名单）。检查结果 MUST 区分错误与警告：存在错误时执行 MUST 被阻断；仅有警告时执行 MUST 允许并明示警告内容。

#### Scenario: DQL 语法错误被阻断

- **GIVEN** Dataview 可用且用户输入的 DQL 语法错误
- **WHEN** 用户执行语法检查或请求执行
- **THEN** 系统 MUST 展示错误信息并阻断执行

#### Scenario: 搜索语法结构错误被阻断

- **GIVEN** 用户输入的搜索脚本括号或引号不配平
- **WHEN** 用户请求执行
- **THEN** 系统 MUST 展示结构错误并阻断执行

#### Scenario: 仅警告时允许执行

- **GIVEN** 检查结果只包含警告（如未知操作符）
- **WHEN** 用户请求执行
- **THEN** 系统 MUST 展示警告并允许继续执行

#### Scenario: Dataview 缺席时 DQL 检查降级

- **GIVEN** Dataview 未安装或未启用
- **WHEN** 用户请求检查或执行手写 DQL
- **THEN** 系统 MUST 提示无法检查并允许直接尝试执行（执行失败有提示）

### Requirement: 确认与执行步骤

确认步骤 MUST 展示命中文件清单与数量，超上限时 MUST 明示截断。执行步骤 MUST 以分组目录（修改属性 / 整理文件 / 收集与同步）展示可用操作，分发给既有 Action（沿用确认窗与备份回滚）。执行步骤后 MUST 可返回确认或查询步骤重新来过。

#### Scenario: 确认清单与截断提示

- **GIVEN** 查询命中文件数超过批量上限
- **WHEN** 系统进入确认步骤
- **THEN** 清单 MUST 按上限截断并明示已截断

#### Scenario: 分组操作目录分发

- **GIVEN** 用户在执行步骤选定某操作
- **WHEN** 分发触发
- **THEN** 系统 MUST 打开该操作对应的既有确认流程（确认窗 / 选择弹窗），后续行为与既有命令完全一致

#### Scenario: 执行步骤可返回重选

- **GIVEN** 用户在执行步骤发现结果不符预期
- **WHEN** 用户点击返回
- **THEN** 系统 MUST 可回到确认步骤或查询步骤，已填查询状态保留
