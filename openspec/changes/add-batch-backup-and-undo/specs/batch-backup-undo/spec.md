# Spec: batch-backup-undo

## Purpose

为 File Cooker 的全部批量写操作提供执行前快照、持久化历史与逐文件回滚能力，并在回滚前检测文件是否被中途修改，防止静默覆盖用户数据，作为批量写操作（含未来 AI 写入）的信任兜底。

## ADDED Requirements

### Requirement: 批量写操作创建可回滚快照记录

系统 MUST 在 6 类批量写操作（属性编辑、移动、重命名、删除、合并、创建）应用成功后，为本次操作创建一条备份记录，记录每个受影响文件操作前状态，供后续回滚。

#### Scenario: 属性编辑成功生成记录
- **GIVEN** 用户对一批文件执行属性编辑并确认应用
- **WHEN** 所有文件属性写入成功
- **THEN** 系统 MUST 生成一条备份记录，且该记录包含每个受影响文件的操作前内容快照

#### Scenario: 移动成功生成记录
- **GIVEN** 用户对一批文件执行移动到目标目录并确认应用
- **WHEN** 所有文件移动成功
- **THEN** 系统 MUST 生成一条备份记录，且记录包含每个文件的旧路径与新路径

#### Scenario: 创建成功生成记录
- **GIVEN** 用户从未解析链接批量创建文件并确认应用
- **WHEN** 所有文件创建成功
- **THEN** 系统 MUST 生成一条备份记录，且记录包含新建文件的路径与内容快照

#### Scenario: 合并仅记录目标文件
- **GIVEN** 用户执行批量合并到目标文件并确认应用
- **WHEN** 合并成功
- **THEN** 系统 MUST 生成一条备份记录，且仅记录目标文件的操作前内容，不记录仅被读取的源文件

### Requirement: 未启用备份时不改变操作行为

系统 MUST 在备份总开关关闭时，照常执行全部批量写操作，但不创建任何备份记录。

#### Scenario: 关闭开关后属性编辑照常执行
- **GIVEN** 备份总开关为关闭状态
- **WHEN** 用户执行属性编辑并确认应用
- **THEN** 文件属性被正常修改，且历史中 MUST 不出现对应备份记录

### Requirement: 操作取消或失败时不产生备份记录

系统 MUST 在操作被取消或应用中途失败时丢弃本次备份记录，不留可见残留。

#### Scenario: 确认前取消无记录
- **GIVEN** 用户已触发批量写操作但尚未应用
- **WHEN** 用户点击取消
- **THEN** 系统 MUST 不产生任何备份记录

#### Scenario: 应用中途失败无残留
- **GIVEN** 用户在确认模态框中点击应用
- **WHEN** 写入过程中抛出异常
- **THEN** 系统 MUST 丢弃本次备份记录，历史中 MUST 不出现该记录，且用户收到失败提示

### Requirement: 从历史中逐文件回滚

系统 MUST 允许用户在历史记录中对单次操作内的一个或多个文件发起回滚，并按变更类型还原：内容类用操作前内容覆盖写回、路径类反向重命名、创建类删除新建文件、删除类用操作前内容重建文件。

#### Scenario: 内容类文件回滚
- **GIVEN** 历史中存在一条属性编辑记录，目标文件此前被写入新内容
- **WHEN** 用户勾选该文件并确认回滚
- **THEN** 该文件内容 MUST 恢复为操作前快照

#### Scenario: 移动类文件回滚
- **GIVEN** 历史中存在一条移动记录，文件从旧路径被移动到新路径
- **WHEN** 用户勾选该文件并确认回滚
- **THEN** 文件 MUST 被重命名回旧路径，且指向该文件的链接由 Obsidian 自动更新

#### Scenario: 创建类文件回滚
- **GIVEN** 历史中存在一条创建记录
- **WHEN** 用户勾选新建文件并确认回滚
- **THEN** 该新建文件 MUST 被删除

#### Scenario: 删除类文件回滚
- **GIVEN** 历史中存在一条删除记录，文件此前被移入系统回收站
- **WHEN** 用户勾选该文件并确认回滚
- **THEN** 文件 MUST 在原路径重建，内容为操作前快照

#### Scenario: 单次操作内部分回滚
- **GIVEN** 一条备份记录包含多个文件
- **WHEN** 用户仅勾选其中部分文件并确认回滚
- **THEN** 仅被勾选的文件被还原，未勾选文件保持现状，记录状态 MUST 标记为部分回滚

### Requirement: 回滚前 drift 检测

系统 MUST 在回滚前比较文件当前状态与操作后快照；当不一致（文件被中途修改）时 MUST NOT 静默覆盖，而是提示用户选择跳过或强制覆盖。

#### Scenario: 内容未变时安全回滚
- **GIVEN** 历史中存在一条属性编辑记录，文件当前内容与操作后快照一致
- **WHEN** 用户对该文件发起回滚
- **THEN** 系统 MUST 直接还原为操作前内容，不产生警告

#### Scenario: 内容被中途修改时默认不覆盖
- **GIVEN** 历史中存在一条属性编辑记录，文件当前内容与操作后快照不一致
- **WHEN** 用户对该文件发起回滚但未选择强制覆盖
- **THEN** 系统 MUST 不覆盖该文件，并提示其已被中途修改

#### Scenario: 内容被中途修改时强制覆盖
- **GIVEN** 同上一场景
- **WHEN** 用户显式选择强制覆盖
- **THEN** 系统 MUST 用操作前内容覆盖写回该文件

#### Scenario: 删除类回滚时原路径已重新存在文件
- **GIVEN** 历史中存在一条删除记录
- **WHEN** 用户发起回滚但原路径已存在其他文件
- **THEN** 系统 MUST 不覆盖该已存在文件，并提示冲突

#### Scenario: 路径类文件已被再次移动
- **GIVEN** 历史中存在一条移动记录
- **WHEN** 用户发起回滚但文件当前路径既非记录的新路径也非旧路径
- **THEN** 系统 MUST 不执行回滚，并提示该文件已被再次移动

#### Scenario: 路径类文件已处于旧路径
- **GIVEN** 历史中存在一条移动记录
- **WHEN** 用户发起回滚且文件当前路径已等于旧路径
- **THEN** 系统 MUST 跳过该文件且不报错（已处于还原后状态）

### Requirement: 备份缺失时降级处理

系统 MUST 在回滚时发现某文件备份内容缺失时，跳过该文件、提示备份缺失，并继续处理其余勾选文件。

#### Scenario: 单文件备份缺失不影响整体
- **GIVEN** 用户对一条包含多个文件的记录发起回滚
- **WHEN** 其中某个文件的备份快照已被删除
- **THEN** 系统 MUST 跳过该文件并提示备份缺失，其余文件正常回滚

### Requirement: 历史记录持久化与保留清理

系统 MUST 将备份记录持久化到 vault 内目录，并在插件重启后可读；超过保留上限时自动清理最旧记录及其备份内容。

#### Scenario: 重启后历史仍可列出
- **GIVEN** 此前已产生多条备份记录
- **WHEN** 插件重新加载
- **THEN** 历史模态框 MUST 仍能列出全部未清理记录

#### Scenario: 超过保留上限清理最旧记录
- **GIVEN** 保留上限为 N
- **WHEN** 新记录提交后历史记录数超过 N
- **THEN** 系统 MUST 删除最旧的记录及其备份内容，保留最近 N 条

### Requirement: 历史与回滚入口

系统 MUST 提供命令入口查看历史并撤销最近一次批量操作。

#### Scenario: 打开备份与撤销历史
- **WHEN** 用户执行"打开备份与撤销历史"命令
- **THEN** 系统 MUST 打开历史模态框，展示记录列表（时间、操作类型、受影响文件数、回滚状态）

#### Scenario: 撤销上次批量操作
- **WHEN** 用户执行"撤销上次批量操作"命令
- **THEN** 系统 MUST 打开历史模态框并聚焦最近一条记录
